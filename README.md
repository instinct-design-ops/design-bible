# Design Bible

Design rules for Shresht's ad design workflow and own brand. Newer dated decisions replace older ones; replaced rules move to `history/`.

## What to read

1. **Always:** [design-bible.md](design-bible.md), the rules in force, each with an ID (W-04, Q-02, L-24...).
2. **For client work:** that client's file in [clients/](clients/): [Alpha One Labs](clients/alpha-one-labs.md), [Lucori](clients/lucori.md). It wins over design-bible.md where they overlap.
3. **When concepting:** [reference/](reference/): layout studies, ad psychology, Meta platform facts, the research feed and approved directions.
4. **Only to understand why:** [history/](history/): changelog, rejected directions, superseded rules, and a snapshot of the Bible before the 25 Nov 2026 split.

## Public copy

This repository is publicly viewable. It contains a sanitized text version of the internal Design Bible. Keep client names and design rules. Omit account emails, credentials, private client Figma or file links, the Studio Desk link, and internal screenshots. The internal Google Doc remains the full version. Apply the same checks before every update.

## Use

Clone this repository once. Pull the latest changes before a new batch, then have the design assistant read design-bible.md and the client's file.

This repository contains workflow guidance and references, not a license to reuse client assets.
